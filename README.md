# 🎁 Community TG Monitor (多社区抽奖与热帖监控 Bot)

> 默认采用轻量 RSS 客户端的多社区（NodeSeek + 烧饼论坛 sb.sb）抽奖/福利/特价新帖监控与 Telegram 双向交互机器人；烧饼签到可选浏览器运行时。

---

## ✨ 核心特性

- 🌐 **双社区官方源支持**：
  - **NodeSeek** (`https://rss.nodeseek.com/`)：全站实时流监控。
  - **烧饼论坛** (`https://sb.sb/rss.xml`)：RSS 用于新帖观察和自定义关注词；自动抽奖/红包检测只采用论坛官方标记。
  - 首页每 30 秒快速发现，`/prize/` 与 `/redpacket/` 每 5 分钟补漏；标记事件与 RSS 分开去重，避免“RSS 先出现、后加标记”导致漏报。`/lottery/` 是站内彩票，不是抽奖主题列表。
  - RSS 和公开列表可匿名读取；签到与互动通知使用登录 Cookie，是否可用取决于站点当前访问限制。
- 🧠 **NodeSeek 双阶段 AI 语义判定**：
  - 不设关键词或板块前置门槛，每篇新帖由 Jev 批量判断输入安全、活动状态、免费权益、受众和参与机制；明确通过或拒绝直接结束；
  - 仅待定项交共享 Gemini 主模型一次终审，结果明确通过才通知；拒绝、仍不明确、格式/引文错误或接口失败均记录原因并结束，不新增人工队列或自动重判；
  - Jev 与 Gemini 连接、密钥和初筛阈值由服务器配置，Telegram 不再提供编辑或连接测试入口。
- 📊 **今日汇总与统计详情**：
  - 分开统计发现活动、关注词命中和活动通知发送结果，显示当天截至查询时刻的简要汇总；
  - 活动通知“发送成功”仅表示 Telegram 接口接受，不包含签到、私信、指令和日报，也不表示收件端已读。没有发送记录时不计算成功率；
  - 自动参与按统计日期从独立账本读取、按活动去重，展示自动参与成功、账号查询确认已参与、已跳过和提交异常；旧策略记录及等待重试仅在确有记录时显示；另列当前等待队列和当日保守预算占用。查询确认不归因为自动提交，预算不代表实际扣饼，参与不代表中奖或到账。关闭推送或参与后仍可查看当日历史，账本异常明确显示不可用。
  - 每日北京时间 **22:00** 准时向 Telegram 推送运行日报，随时发送 `/report` 查阅实时看板。
- 🍪 **烧饼论坛自动签到与全量通知（可选）**：
  - 支持配置 `SBSB_COOKIE` 自动开启每日自动签到（北京时间每天 08:05 自动执行并回传连续天数、烧饼资产与等级）；
  - 使用当前官方 `/checkin/` 表单，提交后核验“今日已签到”才记录成功；统计缺失显示“暂未获取”。遇到人机验证时每天提醒一次，当天停止重复提交、继续查询；在浏览器完成签到后可自动确认。调度每 5 分钟检查，08:05 起执行。
  - 可选浏览器路径使用网站原本的 Cap 组件和提交事件，失败后不补发 HTTP 请求。只查询已签到时明确标为“查询确认”，不归因为本程序提交。
  - Telegram 的 `/signin`、`/checkin` 及签到按钮均只查询签到与资产，不触发手动提交；08:05 后台自动调度保持；
  - 轮询互动通知（`/u/{uid}/notifications/`）与私信箱（`/messages/`）；互动按唯一记录去重，私信目前只提醒新对话，已有对话后续消息不保证再次提醒。
  - 每轮从官方登录导航重新识别当前 UID，购买靓号后可自动切换；通知页再次核对身份。识别失败不复用旧 UID、不使用固定账号兜底，也不跟随重定向；保留已有通知与活动去重记录。
- 🎁 **烧饼红包与抽奖自动参与（默认关闭）**：
  - 只处理官方标记的普通抽奖及红包，提交前复查费用、截止时间、自己的参与状态和原帖。资格判断采用 Jev 初筛、Gemini 终审两轮：初筛明确通过则继续、明确不通过则跳过；待定时由共享 AI_MODEL 做一次独立终审，返回限定结论及逐字原文引用，代码核对字段/类型/引文后明确通过才继续，其余结果（含仍不明确、调用失败）记录原因并跳过，不转人工、不无限重判。审核制、程序无法满足的附加任务、验证要求仍直接跳过，AI 不能覆盖这些程序检查。
  - 每次最多 10 饼、北京时间每天最多 50 饼。收费抽奖按每次 10 饼保守预留，包括已确认与结果未明的提交，因此每天最多 5 个收费抽奖；红包不占收费额度。不设每日参与次数上限，保留随机等待、冷却、防重复及内容条件筛查。
  - 发现活动后随机等待 1–5 分钟，两次提交的冷却时间随机为 90–180 秒；实际参与时间还受轮询、排队和模型耗时影响。等待与冷却期限写入账本，重启后不重抽或集中秒回；到期重新获取页面，活动结束或已参与就跳过。等待不会占用提交预算，也不会阻塞监控或签到线程。
  - 普通抽奖使用论坛按钮的预置回复；红包根据本账号登录后可见的首帖正文生成简短回复，不编造个人经历、已完成任务或中奖到账。复用已有 AI 配置，不需要开启 NodeSeek AI 判定。
  - TypeSafe 与回复模型只接收提取的标题、首帖正文和经过验证的官方报名说明，不发送整页 HTML、Cookie、CSRF、表单字段或页面中的账户身份。普通交易条款、讨论邀请和与本帖红包无关的站外活动不算参与门槛。可执行的回复字数要求由代码识别和校验，支持阿拉伯数字、中文数字、最少/最多/精确字数及范围，在 1–80 字内生成符合要求的回复。两轮资格判断都可见完整原文与官方控件，同时用代码剔除完整字数领取语句后的文本判断其他附加任务，不为同一条件追加多轮复核；与字数并列的注册、关注等条件完整保留。原文输入安全检查不使用剔除后的文本。
  - 保存两轮资格结果、筛查分数和草稿拒绝类别。红包正常按正文生成回复，草稿最多重写一次；这属于文案生成校验，不追加资格裁决。仅两份草稿都未通过文案检查时使用受控中性感谢兜底，字数仍由代码满足。原帖安全、参与条件及提交前复查均继续执行，生成/筛查服务不可用直接跳过，不触发兜底；不保存不安全的拒绝原文。策略版本 5 让旧策略中零费用、无提交/传输/HTTP证据的内容或条件待定记录重新随机检查一次，随后通过或跳过。新版终态不再重排；已参与、提交中或结果未明记录不会重发。NodeSeek 的历史 AI 分类复核队列不在此机制范围内。
  - 参与账本独立于通知去重，提交前落盘。新提交保存经校验的本账号标识和拟发文案；结果不明时每隔至少 5 分钟只读补查，每项最多 3 次、每轮最多检查 1 项，随机红包最多查 5 页；仍未确认则保留结果未明与预算，不再自动提交。旧记录缺少提交前身份依据时保持原样。提交后的确认只允许同一主题页及数字 `reply` 定位链接，查询最多跟随两次经过校验的站内跳转；只有接受响应与官方本账号参与/同文案回帖都确认才归因为程序提交，后续只读补确认只记为账号查询确认。
- 📱 **Telegram 原生交互式管理**：
  - 自动注册 Telegram 官方快捷指令菜单（输入 `/` 即可一键点选）；
  - 支持 **`/sources` 网站独立开关**，可一键暂停/开启特定网站推送；
  - 支持 **Inline Keyboard 按钮一键点选删除**，无需手动打字；
  - 支持 **对话引导式添加**，点击 `/add` 直接打字发送即可入库。
- 🐳 **多架构 Docker 镜像支持**：默认轻量镜像发布至 GitHub Container Registry（`linux/amd64` 与 `linux/arm64`）；浏览器候选另用 Playwright 镜像，体积与启动时内存占用更高。

## 📸 Telegram 交互指令

首页只保留 **签到与资产、今日汇总、参与记录、设置** 四个入口：

| 指令 | 用途 |
| --- | --- |
| `/status` | 打开首页，查看各项业务当前状态与本轮签到结果 |
| `/signin` | 只读查询官方签到与资产，卡片可刷新查询或返回首页 |
| `/report` | 今日参与结果、通知计数、排队与抽奖预算预留 |
| `/records` | 分页查询全部参与账本，包含已参与、跳过和提交异常的活动 |
| `/settings` | 直接点 NodeSeek 推送、烧饼推送、烧饼自动参与的当前状态开关；管理关注词 |

设置中不再提供总暂停按钮、模型/API/密钥编辑或连接测试。状态开关使用明确的目标值，重复点旧按钮不会反向切换；保存失败时保持旧值。关闭烧饼活动推送不影响自动参与，关闭参与不影响推送；NodeSeek 推送开关仍沿用现有语义，也控制其 AI 队列执行。

参与记录只读展示账本，不会触发重新参与、模型复核或补回复。二审不通过、仍不明确或服务失败直接显示“已跳过”；提交中单独显示，不算异常；“提交异常”表示提交阶段发生异常且没有最终确认，详情说明未知是否成功、不会重复提交，保留原预算和防重。查询确认与本程序提交仍分开。新处理的记录保存最多8000字符的首帖正文供查询；历史没有保存的正文、发帖时间、实际回复时间显示未记录或暂未获取，不把发现时间或尝试提交时间当作真实发帖/回帖时间。

`/sources`、`/keywords`、`/add`、`/del`、`/cancel` 等旧查询与关注词指令继续兼容；旧 AI 设置/测试按钮跳转到设置且不再改配置或调用模型。旧 `/pause`、`/resume` 仅作兼容指令保留，不列入菜单；原暂停状态不会静默清除，若仍生效，设置页提示使用 `/resume` 恢复。签到、签到通知和定时日报仍遵循原运行规则。部署后才会注册新的快捷指令，本地生成面板不会更新真实 Telegram 菜单。

旧配置中的 `SBSB_PARTICIPATION_MAX_DAILY` 已停用并忽略；无需清理环境变量即可解除次数上限。日报和状态保留参与次数统计，不再显示次数上限分母。

## 🛠️ 环境变量与凭证获取指南

在部署前，你需要准备以下变量并填入 `.env` 文件中：

| 环境变量 | 是否必填 | 默认值 | 说明与示例 |
| :--- | :---: | :---: | :--- |
| `TG_BOT_TOKEN` | **必填** | 无 | 你的 Telegram Bot API Token，用于发送消息和接收指令交互 |
| `TG_CHAT_ID` | **必填** | 无 | 你的 Telegram 个人纯数字 UID（仅允许管理员本人操作并接收私信推送） |
| `SBSB_COOKIE` | *可选* | 空 | 烧饼论坛登录 Cookie（填入后自动激活每日 08:05 签到、查分与私信/回帖通知） |
| `SBSB_BROWSER_SIGNIN` | *可选* | `0` | `1` 使用浏览器签到，须以 `Dockerfile.browser` 构建；正常执行站点验证，服务端拒绝后当天只查询 |
| `SBSB_BROWSER_MODE` | *可选* | `headless` | `desktop` 使用临时 Xvfb 中的完整 Chromium 与本地 CDP；browser Compose overlay 默认采用此模式 |
| `SBSB_AUTO_PARTICIPATE` | *可选* | `0` | `1` 开启上述红包/普通抽奖自动参与，需 Cookie 与 TypeSafe 筛查配置；终审与红包文案还需现有 Gemini 配置 |
| `TYPESAFE_API_KEY_FILE` | *可选* | 空 | TypeSafe 密钥文件路径，如 `/app/data/participation_typesafe.key`；文件权限应为 `600`，不要提交仓库或打入镜像 |
| `TYPESAFE_API_KEY` | *可选* | 空 | TypeSafe 密钥的环境变量方式，优先于密钥文件；供两站初筛及烧饼内容安全检查，不在状态卡片显示 |
| `AI_API_KEY` | *可选* | 空 | OpenAI-compatible API Key（推荐直接在 .env 注入，免除在 TG 对话框输入密钥） |
| `AI_ENDPOINT` | *可选* | 空 | API 基础地址，如 `https://api.openai.com/v1` 或 `https://api.deepseek.com/v1` |
| `AI_MODEL` | *可选* | 空 | 两站终审与红包回复的共享模型；本部署为 `gemini-3.8-flash-high` |
| `AI_JUDGE_MODEL` | *可选* | 空 | 旧兼容配置；新 Jev/Gemini 级联不读取此项，终审统一使用 AI_MODEL |
| `AI_ACCEPT_THRESHOLD` | *可选* | `0.90` | NodeSeek Jev 初筛通过阈值（范围 0.70～0.99），不作为 Gemini 自报置信度 |
| `AI_ENABLED` | *可选* | `true` | 是否启用 NodeSeek AI 语义判定（配置上述三项后默认激活） |
| `MONITOR_SOURCES` | *可选* | `nodeseek,sbsb` | 启用的公开源，可用逗号分隔过滤（支持 `nodeseek`, `sbsb`） |
| `DATA_DIR` | *可选* | `/app/data` | 数据持久化存储路径 |

## 🚀 极速部署

### 方式一：Docker Compose（推荐）

#### 1. 创建目录与配置文件
```bash
mkdir -p community-monitor && cd community-monitor

# 创建配置文件 .env
cat << 'ENV_EOF' > .env
TG_BOT_TOKEN=YOUR_TELEGRAM_BOT_TOKEN
TG_CHAT_ID=YOUR_TELEGRAM_CHAT_ID

# 可选：烧饼论坛 Cookie（配置后自动开启每日 08:05 签到与互动提醒）
SBSB_COOKIE="__Host-bbs_session=你的烧饼论坛Session值"
ENV_EOF

# 安全加固：收敛配置文件权限
chmod 600 .env

# 创建 docker-compose.yml
cat << 'COMPOSE_EOF' > docker-compose.yml
services:
  community-monitor:
    image: ghcr.io/j2st1n/community-tg-monitor:latest
    container_name: community-monitor
    restart: unless-stopped
    env_file:
      - .env
    volumes:
      - ./data:/app/data
    logging:
      driver: "json-file"
      options:
        max-size: "10m"
        max-file: "3"
COMPOSE_EOF
```

#### 2. 一键启动
```bash
docker compose up -d
```

## ⚙️ 持久化与数据说明

浏览器候选使用官方 Playwright Python 1.63.0 镜像及同版本 SDK，支持 ARM64；可在源码目录通过 `docker compose -f docker-compose.yml -f docker-compose.browser.yml up -d --build` 启用。overlay 默认采用 `desktop`：启动临时 Xvfb 和完整 Chromium，经容器内部回环地址上的 CDP 连接，使用原生窗口尺寸和新建私密上下文，不注入浏览器属性覆盖或伪造验证 token。进程环境排除机器人密钥与 Cookie，不发布调试端口；完成或失败后关闭进程并删除临时资料。

浏览器仅在未签到且允许提交时启动；登录过期或站点策略变化仍可能需要处理。只通过组件和合成测试不代表站点接受，必须有真实表单提交和官方已签到确认；表单导航期间只重试已知执行上下文切换的读取，不追加 POST。

若唯一一次业务 POST 已得到允许的成功响应，但浏览器随后读取或交付页面时报错，主程序会再做一次官方 GET。只有该次查询也确认本轮已签到才报提交成功；查询失败或仍未签时保留结果待确认，不补发业务或验证请求。明确验证拒绝、业务响应失败或重复提交不会进入补确认路径。

### 签到状态与跨日

论坛签到周期按 UTC 日界，即北京时间每天 08:00 开始，计划 08:05 执行。完成日期、停止提交标记与签到时间使用同一周期；凌晨查询显示上一轮结果，不会把上一轮已签到记成下一轮完成。活动日报和参与金额预算仍按北京时间日历日期统计。

签到反馈区分：程序提交且官方确认、仅查询确认已签、查询确认未签、提交结果待确认和查询不可用。验证码组件存在或一般网络异常不能作为人机验证拒绝、登录失效或断签的证据。签到确认和余额/等级查询独立：附加字段失败不撤销签到成功；缺失字段不填 0，之前同周期已核验的字段会标记“此前核验”。等级从积分页的当前等级节点提取，不取下一级或等级阶梯。

`checkin_state.json` 版本 2 保存签到周期、官方核验来源/时间/字段、最新查询结果与独立通知接口结果。旧版仅有完成日期的记录先通过 GET 核验升级，不把旧日期本身当作程序提交证据，也不重复发送已有成功通知。记录损坏时停止新提交并提示核对，不重置记录。

允许自动流程前会保存提交保护标记，自动与手动入口串行处理；中断留下的未确认标记只允许查询恢复。TG 通知未确认会单独记录，不能通过再次签到补发通知；发送接口接受也不是 TG 收件端验收。

验证接口取自签到表单，允许论坛自身与其官方页面声明的 `https://capjs.net` 服务，仅放行该表单对应的 challenge/redeem 与必要预检。论坛会话仅绑定 `sb.sb`；访问外部验证服务时移除 Cookie 和 Authorization。异常只报告安全阶段与类型，不输出接口响应、会话或验证凭据。

原组件的客户端错误只保留白名单 code；事件 message、token 和未知值不会写入日志。服务端返回 `automated_browser_detected` / `instr_automated_browser` 时明确报告当前运行方式被拒绝，当天停止提交。该浏览器候选无法保证永久通过站方策略，失败时应检查安全阶段日志。

数据持久化保存在挂载的 `./data` 目录下：
* `settings.json`：存储你动态配置的关键词、网站开关和推送状态；
* `seen_ids.json`：存储已扫描的公开帖子 ID 历史，带各社区前缀，避免重启后重复推送；
* `sbsb_events.json`：分别存储烧饼论坛官方抽奖与红包标记事件，首次启用静默建立历史基线；
* `sbsb_participation.json`：活动参与账本与收费预留，提交前原子落盘。`confirmed` 表示官方确认已参加，`submission_accepted` 区分本轮响应证据；`reserved` / `uncertain` 永不自动重试。不要为重试删除账本。随机红包会查阅最多 5 页历史回帖，更多页数停止自动提交；确认报名不代表中奖或到账；
* `participation_typesafe.key`：可选的 TypeSafe 筛查密钥文件，单独保存且权限为 `600`；筛查缺失或不可用时停止新参与；
* `ai_secret.json`：兼容此前保存的 AI API Key，权限为 `600`；新菜单不再接收或修改密钥，推荐使用服务器环境变量；
* `nodeseek_ai_state.json`：保存待判定及最近分类审计记录。新分类的拒绝、不明确和服务故障直接记历史终态，不自动重判。旧 `review` 历史数据保留但不新增人工任务；旧待重试项至多运行新级联一次，原已处理/去重记录保持。
* `seen_msgs.json`：存储已扫描的烧饼论坛私信与互动通知唯一去重键，暂停期间也更新；
* `daily_stats.json`：记录每日算法扫描、过滤拦截与命中统计；
* `checkin_state.json`：保存版本2的签到周期、核验字段、提交保护标记和独立通知接口结果。
