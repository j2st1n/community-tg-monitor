# 烧饼自动参与的第二轮终审

资格初筛只做一次 TypeSafe Noul 批量判断，分别检查原文输入安全、正文有效性和额外条件。额外条件概率不高于0.15时直接通过，不低于0.85时直接跳过，中间区间交给一次 TypeSafe Choice 终审。终审使用完整原文、代码归一化后的条件文本和独立验证的官方报名说明，不携带上一轮模型分数或结论，不再追加第三轮条件判断。

终审仅在选择ordinary_entry且对应概率至少0.80、additional_action不高于0.20、unclear不高于0.10时通过。选中值必须是完整合法分布中的最高概率项；confidence不单独作为放行依据。其他结果分别记录终审拒绝、仍不明确或调用失败，持久化为skipped，重启与轮询均不再重判，不转人工。明确审核制、不可执行字数、额外表单、人机验证、身份/费用/时效/防重检查不受终审覆盖。

代码先识别可执行字数语句，两轮资格判断共享原文和去除这些语句后的条件文本；输入安全始终检查完整原文。推广代理试用、机器人邀请码或词元兑换的操作需要明确绑定论坛红包领取才算该红包的附加条件。回复生成与最多一次文案重写、受控兜底仍属于独立文案检查，不是继续重试资格裁决。筛查或生成服务失败直接跳过；主题GET临时失败仍允许原有最多三次页面重试。

策略版本5让旧review记录中已知内容/条件类原因、零费用、无任何提交/HTTP/传输证据的项目重新随机检查一次，旧v1跳过项和v2/3红包重排兼容条件保留。旧任务会先读官网：已经参与或结束即终止，不能把重新检查旧任务计为当天新发布的活动。新策略不产生review；旧NodeSeek AI分类服务复核队列不在本次范围内。

新提交在唯一业务POST前持久化账号标识和拟发文案。若提交结果未明，后台只做GET补确认：至少间隔300秒，每项最多三次、每轮最多一项，随机红包最多读取五页；身份不一致、大历史或查询失败均保留未明，不重新提交。GET确认记为submission_accepted=false，原错误、原提交时间与预算保留；匹配到实际自有回复才将拟发文案记为已核实回复。旧未明记录缺少提交前账号依据则保持，不能凭当前Cookie反推旧提交身份。没有修订HTTP跳转白名单，也没有推断旧post_redirect_unconfirmed的具体原因。

等待60–300秒、提交冷却90–180秒、每次10饼/每天50饼保守预留、不设参与次数上限、推送与自动参与开关分离，均保留。签到、验证码处理与NodeSeek AI业务逻辑未修改。

验证使用断网合成测试覆盖两轮允许/拒绝/不确定/接口异常、终态重启防重、真实附加条件与外部推广关系上下文、字数与输入安全、预算和提交前变化，以及GET补确认的身份、页数、次数和预算边界。部署保留原镜像、配置、签到与业务账本；先备份运行源码，失败仅回滚源码。生产验收区分源码加载、合成流程验证、自然任务及官方账号确认，不把测试或排队当成实际回帖成功。
