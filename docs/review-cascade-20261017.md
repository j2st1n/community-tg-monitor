# Jev初筛与Gemini终审

NodeSeek活动识别与烧饼参与资格统一使用分级判断：Jev初筛明确通过或拒绝即结束，仅待定项交共享`AI_MODEL`一次终审。本部署使用`gemini-3.8-flash-high`。旧`AI_JUDGE_MODEL`保留兼容读取，不参与新级联路由。两个业务的语义问题和规则独立，不能用“这是活动”替代“本账号可以参与”。

NodeSeek在一次Jev请求中批量检查输入安全、正文有效性、活动时态、免费权益、受众、参与机制及排除意图，同时判断活动类型。安全和有效正文门槛仍独立；明确否定任一必要条件则跳过，明确满足全部条件才推送，其余进入一次Gemini终审。给模型的输入只包含有界公开RSS标题和正文，不含作者身份、账号状态、Cookie、API凭据或源代码。用户关注词直通规则保持。

烧饼保留已有Jev安全/条件初筛，额外条件概率不高于0.15直接通过、不低于0.85直接跳过，中间区间由Gemini独立终审。两轮共享完整有界首帖、代码处理字数后的条件文本和经过独立核验的官方报名说明。终审不携带初筛分数，区分本论坛奖品与帖子广告中的其他产品试用/外部权益。明确附加任务、验证、费用、身份、截止、已参与及提交防重仍由代码约束，终审不能覆盖。

Gemini终审仅返回有限枚举结论及1至3项逐字引用，每项使用允许的原文字段和最多300字符的引用。代码核对对象键、字段、类型和引文是否存在，明确允许才继续。不要求Gemini生成校准概率，不把自报confidence当作准入门槛；这改变了旧Jev Choice终审的分布校验方式。终审HTTP400也不自动重发。引文一致只能验证引用真实存在，不能保证语义结论正确，仍需自然样本观察。

终审拒绝、仍不明确或服务失败终态跳过，服务故障使用独立安全错误码，不伪装成语义拒绝。NodeSeek新处理任务不再失败退避至人工队列，老review记录保留、不迁移、不重新处理；旧待重试项目至多运行新级联一次。分类结束继续持久化已处理标识，避免重启和后续RSS重新入队。烧饼原有终态不重排，旧已参与/提交中/提交异常记录保留。

红包文案仍由共享Gemini生成，Jev检查文案安全；最多一次改写和受控中性兜底仍为独立文案流程。随机等待、冷却、每次10饼/每天50饼保守预算、业务POST防重及有限GET补确认保持。签到与08:05后台调度源码不变。此次部署还包含用户已确认的精简TG菜单和只读签到按钮。

验证分为离线合成回归、Oracle相同候选的断网回归、只含合成原文的真实模型接口核验，以及部署后的源码/配置/账本保护检查。真实接口测试不调用论坛、TG，不提交活动，不发送实际帖子或账号派生数据给额外审查模型。上线加载与合成接口测试不能代替自然新帖参与成功；发送端接口受理也不能代替TG收件核验。
